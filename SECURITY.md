# Paksward security

What protects your vault, what it does not, and what you must do yourself.

## The design in one paragraph

Your entries are encrypted with a random vault key (Fernet: AES-128-CBC + HMAC-SHA256). That key is
stored twice, each copy encrypted under a different key:

| Copy | Unlocked by | Made from |
|---|---|---|
| Password copy | master password **and** Secret Key | Argon2id (64 MiB, 3 passes, 4 lanes) over the password, mixed with the Secret Key |
| Recovery copy | Recovery Key | the Recovery Key alone |

The **Secret Key** and **Recovery Key** are 160 random bits each, generated by Paksward (`secrets`), shown
as `PWSK-…` / `PWRK-…` with a checksum. They are not chosen by you, so they cannot be guessed.
The Secret Key is stored on your device **outside** the data folder.

## Is guessing impossible?

Against someone who copies your data folder (backup, cloud sync, stolen disk image, a friend you sent it to): **yes, in the
practical sense.** Opening it needs 160 random bits that are not in that folder. Trying them all is
2^160 operations, far beyond any computer that exists or is plausible. This holds however weak your master password is.

Honest limits:

* "Impossible" means computationally infeasible **if the keys stay secret and are random**. It is not a mathematical proof,
  and nobody has independently reviewed this design. Have it reviewed before trusting it with anything critical.
* Someone with access to your **whole computer account** (data folder *and* device key) must still guess your
  master password. Argon2id makes each guess cost 64 MiB of memory and about a tenth of a second, so a long password
  matters here. The lockout counter does **not** help against this: a person with the files can ignore the app.
* Anyone who holds your **Recovery Key** can open the vault without your password. Store it apart from your password.
* Malware running as you can read the vault while it is open, log your keystrokes, and read the clipboard. No password manager can prevent that.
* **Lockout is permanent.** The vault opens with (password + Secret Key) or with the Recovery Key. Lose both routes (for example the password and the Recovery Key, or the Secret Key and the Recovery Key) and nobody can open it. There is no back door and no server to ask.
* The password strength meter is a rule of thumb. It models dictionary words, years, common passwords and look-alike tricks, and errs low, but it cannot know every password list an attacker has.

## The one online feature

"Check now" on the Watchtower page asks haveibeenpwned.com (Have I Been Pwned range API) whether a password appears in known breaches.
It uses k-anonymity: only the first 5 characters of each password's SHA-1 fingerprint are sent, over HTTPS, and the match is made locally.
The password, the rest of the fingerprint, your email and the site names are never sent. The request carries a generic client name, no account.
It runs only when you press the button. (The service can still see that some computer asked about those 5-character prefixes.)

## The lockout

Five wrong attempts lock the **login screen** for 24 hours. It stops someone using your running app. It cannot stop someone
guessing against a copy of the files, which is why the Secret Key exists.

## The local server

The interface is served from `127.0.0.1` only. API calls need a random token that exists only in the link printed at start-up.
The Host and Origin headers are checked (blocks DNS rebinding and other websites), the page loads nothing from the internet
(Content-Security-Policy), only fixed file types are served, and requests are size- and time-limited.
Anyone else logged in to the **same computer** can still reach the port, but cannot use it without the token.

## Files

`users.json`, vault files and the device key are written atomically (temporary file, flushed to disk, then swapped in) with
owner-only permissions on macOS/Linux. On Windows the permission step is skipped and your user profile's own access rules apply.

## Reporting a problem

Open an issue without including real keys, vaults or passwords.
